# Kuno design contract

- **Brand idea:** Kubernetes resources become a navigable tree; a selected node turns the tree into a distinctive K-shaped mark. No Kubernetes wheel or mascot.
- **Landing page:** Portuguese (pt-BR) is the default at the site root; the English page lives at `/en/`, sharing `styles.css` and `demo.js`. Demo strings come from `window.KUNO_I18N`, defined inline per page, so the JS stays language-neutral. Both pages declare `hreflang` alternates.
- **Landing page purpose:** a short, concrete promise, then proof through the real terminal UI and a hands-on, browser-local demo. The install command sits in the hero, where a call to action used to be; there is no "explore the demo" button.
- **Section titles match the nav:** every anchor in the header names the section it opens (the workflow section is headed "Por que Kuno" / "Why Kuno"), so a clicked link never lands on a differently titled block.
- **Logs get their own treatment:** the interactive demo has a raw/pretty switch (`m`, as in the app) that mirrors `parse_log_line` and `_structured_text` from `kuno/logs.py`: JSON lines get a short timestamp, a coloured level, a category and `key=value` fields; anything that is not a JSON object passes through untouched. The site calls the mode "pretty" while the app's mode value is `structured`; keep both words in mind if either is renamed. The static proof is a stacked pair of strips (raw above pretty) cropped from full-screen captures at the same scroll position, so the same five log lines can be compared; the crop relies on the capture size fixed in `capture_site_screenshots.py`.
- **Hosting and metadata:** the site is published at `https://cadumagalhaes.dev/kuno/` with English at `/en/`. Canonical, `hreflang`, Open Graph and Twitter tags are absolute and point at that host; move them together if the path changes.
- **Social cards are generated, one per language:** `scripts/build_og_cards.py` renders `site/assets/og-pt.png` and `og-en.png` from one layout with translated copy, fitting the headline to the column; the terminal capture is embedded, so the source carries no machine paths. The PNGs are committed and CI runs the script with `--check`, which fails when copy or a screenshot changed without regenerating. `make og` regenerates, `make og-check` verifies. `scripts/og-preview.html` shows both cards locally (it is not part of the published site).
- **Discovery files:** `robots.txt` allows crawlers and deliberately carries no `Content-Signal` until a training policy is chosen; `llms.txt` summarises the project and links PyPI, the README and both landing pages. Neither is a ranking lever.
- **Palette:** Paper-white page, near-black type, one electric-blue action/accent. No gradients or decorative cards. The product demo keeps Kuno's real terminal treatment; its theme switcher shows Nord, Dracula, Catppuccin Latte, and Solarized Light to cover distinct dark and light palettes. `site/assets/themes.json` and the theme captures are exported from Textual's registered `Theme` objects, and the browser demo uses those same resolved colors rather than a separate hand-picked palette.
- **Typography:** System sans-serif across the page; monospace stays inside terminal/code surfaces. The generated Boska type direction was dropped because it clashed with a developer tool and added a remote font dependency.
- **Interaction:** The demo uses clearly labeled synthetic cluster data only; it never reads kubeconfig or contacts a cluster. Keyboard and pointer navigation both work. The theme preview is local and changes both the app capture and demo palette; users set `ui.theme` in config or run `:theme <name>` in Kuno.
- **Assets:** Product screenshots come from Kuno running against isolated fixture data. The K-shaped resource tree is a hand-drawn SVG and must remain legible at favicon size. Screenshots open in a native modal `<dialog>` (Esc, backdrop, or the close button, with the browser returning focus); on phones the enlarged capture scrolls horizontally rather than shrinking back to thumbnail size. `capture_site_screenshots.py` is byte-reproducible: the status-line clock is pinned, Textual's per-run element ids are normalized, and the table screens get a longer settle pause, so recapturing only shows a diff when the UI itself changed.
- **Two hand-maintained pages:** `scripts/check_site_parity.py` compares the body outline and ids of both pages so a section added on one side cannot silently drift. Run it after touching either page.
- **Non-goals:** This is a focused landing page, not a documentation portal or a fake live Kubernetes connection.
